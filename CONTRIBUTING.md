# Contributing to StintikVPN

Спасибо, что хотите помочь проекту. Ниже — короткая памятка: как устроен
репозиторий и что нужно сделать, чтобы ваше изменение попало в `main`.

## Структура проекта

```
.
├── docs/                     # сайт на GitHub Pages
│   ├── index.html            # разметка: только контейнеры, без ссылок на подписки
│   ├── style.css             # стили
│   ├── script.js             # логика: рендер, фильтры, QR-код, тема
│   └── data.json             # ЕДИНЫЙ ИСТОЧНИК ДАННЫХ: подписки и прокси
├── scripts/
│   └── sync_readme.py        # генерация разделов со ссылками в README
├── .github/
│   ├── workflows/            # CI: проверка ссылок, зеркала, синхронизация README
│   ├── ISSUE_TEMPLATE/       # формы для issue
│   └── PULL_REQUEST_TEMPLATE.md
├── README.md                 # русский
├── README_EN.md              # english
├── README_CN.md              # 中文
├── README_IR.md              # فارسی
├── CONTRIBUTING.md
├── SECURITY.md
└── LICENSE                   # MIT
```

## Правила

1. **Сначала `docs/data.json`.** Подписки и Telegram-прокси добавляются и
   обновляются только там. Сайт и README читают этот файл — захардкоженных
   ссылок в коде быть не должно.
2. **У каждой подписки должен быть `id`** — короткий стабильный ключ
   (`black-main`, `white-cidr`…). Он используется генератором README, чтобы
   подписи в разных языках не расходились.
3. **Разделы со ссылками в README не редактируются руками.** Их генерирует
   `scripts/sync_readme.py` из `data.json`, а CI обновляет README сам.
   После правки `data.json` запустите скрипт локально:
   ```bash
   python3 scripts/sync_readme.py
   ```
4. **Не дублируйте URL в HTML.** В `docs/index.html` нет ссылок на подписки и
   прокси — только контейнеры `#sub-list` и `#proxy-list`, которые наполняет
   `script.js`.
5. **Поле `updated`** в `data.json` меняется при обновлении прокси. Дата в
   интерфейсе берётся оттуда, дублировать её в JS не нужно.
6. **Ссылки проверяет CI** ежедневно в 06:00 UTC. Мёртвая ссылка — это issue с
   меткой `dead-link`: замените ссылку в `data.json` или удалите её.
7. **Язык коммитов — русский**, формат conventional commits:
   `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `ci:`.
   Пример: `docs: добавляю подписку для мобильных клиентов`.

## Локальная проверка

```bash
# сайт
cd docs && python3 -m http.server 8000

# валидность JSON и синхронизация README
python3 -c "import json; json.load(open('docs/data.json'))"
python3 scripts/sync_readme.py --check
```

## Оформление pull request

- Опишите, что изменилось и зачем.
- Отметьте пункты в [шаблоне PR](.github/PULL_REQUEST_TEMPLATE.md).
- Если менялся `data.json` — приложите обновлённый README (или запустите
  скрипт синхронизации).
- Один PR — одна логичная тема.

## Что не нужно делать

- Не переписывать историю `main` и не форсить push в `main`.
- Не добавлять новые зависимости без обсуждения: сайт намеренно сделан
  без сборки и без фреймворков.
- Не публиковать в репозитории личные данные, ключи и рабочие конфиги.
